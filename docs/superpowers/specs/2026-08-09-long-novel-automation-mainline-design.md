# 通用长篇小说自动化主线设计

## 背景

宫寒小说自动化工作台已经具备 Creative Hub、自动导演、小说工作台、章节执行、任务中心、知识库、写法、角色、世界观、短剧和漫画等模块。第一期大改造不另起炉灶，也不把项目改成某一种平台或题材专用工具，而是在原有基本盘上强化一条清晰、稳定、可恢复的通用长篇小说生产主线。

当前设计面向完全不熟悉小说结构的新手，也兼顾有经验创作者的可控性。系统应该帮助用户从一句灵感推进到可持续章节生产，让用户始终知道当前作品停在哪一步、已经生成了哪些长期资产、下一步应该做什么，以及失败或暂停时如何恢复。

## 目标

第一期目标是构建“通用长篇小说自动化 + 类型模板驱动”的主线体验。

主线流程为：

```text
一句灵感
-> 类型/题材定位
-> 核心主角与关系网
-> 世界/时代/规则
-> 书级契约
-> 卷规划
-> 章纲/任务单
-> 章节正文
-> 审稿修复
-> 状态回灌
-> 下一章
```

第一期完成后，用户应能稳定回答五个问题：

1. 我现在这本书卡在哪一步？
2. 下一步应该去哪里处理？
3. 哪些内容已经保存为后续章节可继承的长期资产？
4. AI 为什么暂停、失败或要求确认？
5. 已生成章节能否继续服务后续章节？

## 非目标

第一期不重写自动导演、不推翻现有 API、不新建一套与原系统并行的小说生产模型。

第一期也不把漫画、短剧、公开介绍站、桌面安装包发布作为主目标。它们保留原入口，等小说主链路更稳后再在后续阶段增强。

第一期不把类型模板做成锁死剧情的规则系统。模板只提供生产约束、默认问题和审稿重点，用户可以修改或覆盖。

## 产品原则

- 保持原项目基本盘：Creative Hub、自动导演、小说列表、新建、编辑、单书工作台、章节执行、任务中心、模型设置、知识库、写法、角色、世界观和衍生入口继续存在。
- 主线优先：用户从首页进入后，默认看到“开始或继续一部长篇小说”的路径。
- 新手友好：页面文案面向用户动作和创作结果，不暴露 `checkpointType`、`DirectorRunCommand`、`workflowTaskId` 等技术词。
- 接口保守：前端交互可以明显升级，但后端优先使用兼容字段、解释层和聚合能力。
- 类型模板驱动：通过宽泛类型模板提升默认规划质量，同时保持通用长篇适配能力。
- 可恢复：暂停、失败、等待确认和质量风险都要转成清晰的用户动作。

## 类型模板

第一期提供宽泛类型模板，模板服务于生产流程，不限制最终作品风格。

建议首批模板：

| 类型 | 默认生产重点 |
| --- | --- |
| 玄幻/奇幻 | 世界规则、力量体系、地图层级、势力冲突、成长节奏 |
| 都市/现实 | 职业身份、社会关系、资源目标、现实约束、人物成长 |
| 科幻 | 技术假设、世界变更点、伦理冲突、探索结构、危机升级 |
| 悬疑/推理 | 核心谜题、公平线索、误导设计、揭示节奏、真相回收 |
| 历史/架空 | 时代秩序、制度限制、势力博弈、人物立场、历史压力 |
| 言情/情感 | 关系推进、情感阻力、亲密度变化、误会与确认、关系代价 |
| 冒险/成长 | 目标旅程、阶段挑战、伙伴变化、奖励与代价、阶段升级 |
| 其他/自定义 | 通用主线、角色动机、世界边界、章节目标、审稿约束 |

模板数据应包含：

- `id`
- 中文名称
- 适用题材说明
- 开书问题
- 规划重点
- 世界观字段提示
- 角色字段提示
- 审稿关注点
- 默认自动化建议

这些模板可以先沉淀为共享配置，供前端新建向导和后端自动导演上下文共同使用。

## 前端模块设计

第一期前端 UI 交互是重点。目标不是全站重绘，而是把原有模块组织成一条更自然的创作流水线。

### 首页：创作驾驶舱

首页优先显示：

- 最近作品继续入口
- 等待处理的导演任务
- “开始一部长篇小说”主按钮
- 本次或近期写作进度
- 快速恢复入口

现有模块入口保留，但主视觉和操作焦点集中到长篇生产主线。

### 新建小说页：类型模板向导

新建页从普通表单升级为分步向导：

1. 选择类型模板。
2. 输入一句灵感。
3. 选择创作目标。
4. 设置自动化程度。
5. 预览系统将如何规划这本书。
6. 启动自动导演。

向导应复用现有新建和自动导演能力，不改变原有接口语义。选择模板后，系统自动补充开书提示、书级定位、规划偏好和审稿关注点。

### 单书工作台：主线状态面板

小说编辑页或单书工作台顶部增加主线状态面板：

- 当前阶段
- 推荐下一步
- 已完成资产
- 待处理事项
- 风险或暂停原因
- 一键继续入口

状态面板不替代原页面，只负责把多个已有模块串起来。

### 自动导演跟进页：人话 checkpoint

自动导演跟进页需要把 checkpoint 解释为用户语言：

- 当前为什么暂停
- 系统已经生成什么
- 需要用户确认什么
- 继续后会发生什么
- 风险提示
- 推荐操作

推荐布局为：左侧阶段时间线，中间 checkpoint 解释，右侧操作区，底部显示已生成资产。

### 章节生产页：写作闭环工作台

章节页面聚合单章生产闭环：

- 左侧章节队列
- 中间正文与版本
- 右侧任务单、审稿、修复和回灌状态
- 顶部显示“这一章是否可以继续影响下一章”

用户应能看懂这一章为什么这样写、哪些问题可以修复、哪些状态已经回灌。

### 任务中心：写作任务解释

任务中心增加面向写作的解释：

- 哪本书
- 哪个生产阶段
- 是否影响主线
- 推荐去哪个页面处理
- 是否可重试

任务事实仍来自原任务系统，解释层只负责降低理解成本。

## 数据流设计

第一期数据流保持原生产链路，只把类型模板作为增强输入。

```text
用户灵感 + 类型模板 + 可选偏好
-> 自动导演候选方向
-> 书级契约 / framing
-> 世界观、角色、卷规划
-> 章节任务单
-> 正文生成
-> 审稿与修复
-> 事实、角色状态、伏笔、质量债务回灌
```

类型模板的约束进入规划和审稿，但不成为不可修改的硬规则。

## 状态解释层

第一期不新增复杂底层状态，优先把已有自动导演任务状态、checkpoint 和章节执行状态翻译成统一解释对象。

解释对象应能表达：

- 当前阶段
- 用户可读说明
- 暂停原因
- 推荐动作
- 可跳转页面
- 风险级别
- 是否可自动继续

示例映射：

| 底层 checkpoint | 用户含义 |
| --- | --- |
| `candidate_selection_required` | 等待选择书级方向 |
| `character_setup_required` | 角色阵容需要确认 |
| `chapter_batch_ready` | 章节任务已准备好，可以开始正文 |
| `replan_required` | 当前质量或规划风险较高，需要决定修复还是重规划 |
| `workflow_completed` | 当前目标范围完成 |

解释层可以先在共享库或前端工具函数中实现，后续再沉到后端聚合接口。

## 后端与接口策略

后端策略是兼容增强。

- 保持现有接口不变。
- 新能力优先通过可选字段、共享配置或轻量聚合接口提供。
- 不删除旧字段，不改名，不改变原字段语义。
- 不用非 AI 的关键词规则替代自动导演中的 AI 结构化理解。
- 如果新增提示词能力，遵守 `server/src/prompting/` 的 Prompt Registry 规则。

如果现有页面需要多次请求才能拼出主线状态，可以新增单书主线概览接口：

```text
GET /api/novels/:id/production-overview
```

接口只做聚合，不改变事实来源。它可以返回：

- novel 基础信息
- 当前自动导演任务摘要
- checkpoint 解释
- 最近章节状态
- 待处理任务数量
- 推荐下一步

## 失败恢复设计

恢复入口应复用现有任务中心、自动导演跟进页和章节执行页。

| 情况 | 推荐入口 | 用户动作 |
| --- | --- | --- |
| 任务失败 | 任务中心 | 查看错误、重试或进入恢复 |
| 等待确认 | 自动导演跟进页 | 确认、调整、继续或重试 |
| 章节卡住 | 章节生产页 | 查看任务单、审稿和修复 |
| 上游资产缺失 | 小说编辑页或对应资产页 | 补齐世界观、角色或卷规划 |
| 质量风险 | 章节生产页或导演跟进页 | 局部修复、记录质量债务或重规划 |

只有全局重规划、不可恢复生成失败、数据完整性风险或运行时安全风险才应停止整本书主链路。局部章节质量问题应优先转为质量债务或局部修复建议。

## 测试与验收

第一期验收链路：

```text
首页
-> 新建小说向导
-> 类型模板
-> 自动导演启动
-> 单书主线状态
-> 等待确认或继续
-> 章节生产入口
-> 审稿修复说明
```

测试覆盖重点：

- 首页主入口存在。
- 类型模板能正确渲染。
- 新建向导不破坏原新建接口。
- checkpoint 能翻译成用户语言。
- 单书工作台能展示推荐下一步。
- 章节生产页能展示任务单、审稿、修复和回灌状态。
- 移动端核心按钮可用。
- 聚合接口如新增，不能影响旧接口。

## 八期路线

### 第 1 期：通用长篇自动化主线与 UI 交互

主线入口、类型模板向导、单书状态面板、导演 checkpoint 解释、章节生产闭环界面。

### 第 2 期：写作资产体系强化

统一世界观、角色、伏笔、质量债务、写法规则入口，让这些资产更明确地服务后续章节。

### 第 3 期：章节质量闭环升级

强化审稿、修复、反 AI 味、风格一致性和连续性检查，让章节稳定变好。

### 第 4 期：任务恢复与长链路稳定性

增强失败恢复、重试、断点续跑、任务冲突提示、运行日志和诊断页。

### 第 5 期：模型路由与成本控制

按规划、正文、审稿、修复、拆书等任务选择模型，显示消耗、失败率和推荐配置。

### 第 6 期：知识库与拆书回灌

让参考资料、拆书结果和写法样本更稳定地进入规划和正文上下文。

### 第 7 期：桌面端与发布体验

优化 Windows 桌面版启动、备份、更新、配置检查、安装包和用户文档。

### 第 8 期：衍生工作坊

在小说主链路稳定后，强化短剧、漫画和视觉资产等衍生模块。

## 实施顺序建议

第一期建议按以下顺序进入实施计划：

1. 建立类型模板共享配置和基础测试。
2. 建立 checkpoint/任务状态解释层和基础测试。
3. 优化首页主入口。
4. 优化新建小说类型模板向导。
5. 优化单书工作台主线状态面板。
6. 优化自动导演跟进页 checkpoint 解释。
7. 优化章节生产页闭环展示。
8. 增加必要的前端契约测试和后端聚合接口测试。

这个顺序先稳定共享概念，再改界面，最后补齐验收链路。
